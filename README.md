# 🐉 Dragon Tasks

Личный Telegram-бот для задач, напоминаний и утренней сводки. Python 3.12, aiogram 3, SQLite.

## Как пользоваться

Отправь текст, фотографию, альбом фотографий, голосовое, документ, видео, аудиофайл или пересланное сообщение. Задача и вложения сохраняются в одном месте.

- «Завтра в 18:00 купить аккумулятор» — бот предложит точный срок; нажми «Всё верно — сохранить».
- «Проверить NAS #работа / через 2 часа» — строгий формат со сроком.
- Сообщение без срока сохраняется без напоминания. Его можно назначить кнопкой.
- Разделы: Учёба, Личное, Работа, VPN. По умолчанию — Личное; метки `#работа`, `#личное`, `#учёба`, `#vpn` выбирают раздел сразу.
- Карточка задачи позволяет менять название, раздел, время, просматривать и добавлять вложения. После добавления вложений нажми «Закончить»; `/cancel` отменяет текущий ввод, сохраняя задачу.

В напоминании **ровно две кнопки: «✅ Выполнено» и «📅 Перенести»**. Перенос предлагает 15 минут, час, три часа, завтра в это же время, календарь или ввод даты и времени. Текст и вложения остаются в задаче. Кнопки «Отложить» нет.

Фотография приходит вместе с текстом напоминания. Если вложений несколько, они приходят последовательно, затем карточка с двумя кнопками. Фото с длинным текстом также отправляется отдельно от карточки. Фото не распознаются автоматически: сохраняется сама фотография и её подпись.

### Чек-листы

Пришли встроенный список Telegram (как новое или пересланное сообщение) либо текст «Продукты» и ниже «Молоко», «Хлеб», «Сыр» с новой строки. Поддерживаются маркеры `-`, `•`, `1.`, `[ ]`, `[x]`, `✅`, `⬜`. Без заголовка список с маркерами сохраняется как «Список задач». Обычный многострочный текст с заголовком и двумя или более строками тоже считается списком. До 30 пунктов, до 200 символов каждый, до 1200 суммарно.

В карточке нажми «☑️ Пункты списка» и отмечай пункты кнопками. Можно снять отдельную отметку или все. Прогресс сохраняется в SQLite и экспорте, при переносе и перезапуске. Напоминание показывает список с выполненными и оставшимися пунктами; отдельное сообщение даёт кнопки отметок. Под основным напоминанием остаются ровно две кнопки. «Выполнено» отмечает весь список. В повторяющихся задачах отметки сохраняются между циклами; для нового прохода нажми «Снять все отметки». Когда Telegram присылает боту изменение отправленного ему встроенного списка, пункты и отметки обновляются. Списки в другом чате после пересылки не связаны с копией в боте. Кнопки бота сохраняют прогресс в его базе; исходное сообщение Telegram они не редактируют. Нативный интерактивный список от имени обычного бота API не позволяет отправить: sendChecklist требует подключённый Business-аккаунт, поэтому напоминание использует текст и кнопки.

### Повторяющиеся задачи

Назначь первый срок, подтверди задачу и нажми «🔁 Повторение»: раз в день, неделю, месяц или год. Напоминания приходят автоматически по Москве, даже без отметки «Выполнено». Эта кнопка отмечает текущий цикл; повторение продолжается. В уведомлении по-прежнему только «Выполнено» и «Перенести». Выключить повторение можно в карточке, выбрав «Один раз».

Месяц сохраняет исходное число: 31 января → 28/29 февраля → 31 марта. 29 февраля при ежегодном повторении становится 28 февраля в обычные годы и возвращается на 29-е в високосные. После простоя приходит одно пропущенное уведомление, затем ближайшее будущее. «Перенести» меняет дату и время, от которых дальше идёт повторение; «Без напоминания» приостанавливает рассылку до назначения срока. Вложения сохраняются.

### Голосовые: бесплатная расшифровка

Отправь ГС на русском до 3 минут и до 10 МБ. Бот автоматически распознает его локально через Vosk, покажет исходную расшифровку и предложенную задачу со сроком. Нажми «Всё верно — сохранить» после проверки или измени текст и время кнопками. До подтверждения это черновик без уведомлений. Пример: «Напомни завтра в восемнадцать тридцать купить молоко». Поддерживаются также «через тридцать минут» и «пятнадцатого октября». Оригинал остаётся вложением; «Распознать» можно нажать повторно для старых ГС.

Платного API и ключей нет. Запись загружается из Telegram на сервер бота, обрабатывается в отдельном процессе и удаляется из временной папки. Сторонним сервисам аудио не отправляется. Официальная модель `vosk-model-small-ru-0.22` загружается по HTTPS один раз в каталог `speech-models` рядом с SQLite (Bothost: `/app/data/speech-models`). Архив проверяется по SHA-256 перед распаковкой. Папка данных не входит в Git. При запуске модель подготавливается в фоне, готовность видна в логе `Free Russian speech ready: Vosk`. Первый запуск требует доступа к alphacephei.com и может занять до 3 минут.

Нужны Linux x86_64, примерно 500–700 МБ доступной RAM на время распознавания (основной бот плюс изолированный worker), место под небольшую модель и FFmpeg из wheel imageio-ffmpeg. Память worker освобождается после каждого ГС; запросы идут по одному, фоновые напоминания продолжаются. Качество компактной модели зависит от дикции и шума: всегда проверяй расшифровку и срок. Без распознанного срока задача остаётся без напоминания до ручного назначения. При ошибке аудио и черновик сохраняются, есть повтор или ручной ввод. На локальной Windows worker с process-group ограничением требует адаптации; целевая среда — Linux Bothost.

### Команды

| Команда | Действие |
| --- | --- |
| `/tasks` | Все активные задачи |
| `/today` | Задачи со сроком сегодня |
| `/overdue` | Просроченные |
| `/lists` | Разделы |
| `/done` | Выполненные |
| `/drafts` | Неподтверждённые задачи с распознанным сроком |
| `/digest 09:00` | Время ежедневной сводки |
| `/digest off` | Выключить сводку |
| `/export` | Свои задачи и сведения о вложениях в JSON |
| `/cancel` | Отменить ввод времени/названия/вложений |
| `/id` | Твой числовой Telegram ID |
| `/help` | Справка |

По умолчанию сводка приходит в 09:00 по Москве. Новые задачи не требуют раздела или срока. Выполненные задачи остаются в истории. Просроченные задачи не повторяют уведомление без переноса.

## Размещение на Bothost

1. В @BotFather создай бота (`/newbot`). Токен вводи непосредственно в переменные окружения хостинга, не в чат и не в GitHub.
2. Размести файлы проекта в корне отдельного репозитория GitHub `dragon-tasks`. Рекомендуется приватный репозиторий.
3. В Bothost создай бота из Git-репозитория. Если он закрытый, владелец должен разрешить Bothost доступ именно к этому репозиторию.
4. Python 3.12, файл запуска `main.py`, команда `python main.py`. Зависимости устанавливаются из корневого `requirements.txt`. Включён Dockerfile для ручной сборки.
5. Задай переменные:

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен @BotFather, обязательно |
| `ALLOWED_USER_IDS` | Разрешённые числовые Telegram ID через запятую, обязательно |
| `TIMEZONE` | `Europe/Moscow` |
| `DB_PATH` | Путь к SQLite на постоянном диске хостинга |

Без токена и списка разрешённых пользователей бот не запускается. Чужие пользователи не получают доступ к задачам. В группах бот не работает.

**Хранилище:** обычный файл внутри контейнера может исчезнуть при пересборке. Подключи постоянное хранилище и укажи его путь в `DB_PATH`. Доступность и конкретный путь постоянного диска нужно проверить в твоём аккаунте Bothost. При Docker bind mount каталог должен быть доступен для записи пользователю `bot`. По умолчанию используется `data/tasks.sqlite3`, это не гарантия сохранности при пересоздании контейнера.

6. Запусти бота и отправь `/start`. Создай «Проверка / через 1 минуту», подтверди её, проверь получение напоминания и перенос с фотографией.
7. Перезапусти и пересобери контейнер, убедись, что задачи сохранились. Не запускай одновременно два экземпляра с одним токеном или общей SQLite.

## Локальный запуск

```sh
python -m venv .venv
# Активируй окружение для своей ОС.
pip install -r requirements.txt
# Скопируй .env.example в .env и заполни значения.
python main.py
```

Тесты: `python -m unittest discover -s tests -v`.

## Надёжность и ограничения

Проверка сроков каждые 15 секунд. После простоя бот догоняет неотправленные напоминания и сводку за текущий день. Временные ошибки Telegram приводят к повторной попытке. При аварии между отправкой сообщения и фиксацией отправки возможен дубль; также после частичной отправки нескольких вложений они могут повториться.

Сроки понимаются в явных форматах: «сегодня/завтра/послезавтра в 18:00», «в пятницу в 15:00», «15.10.2026 09:30», «через 30 минут/2 часа/3 дня». Простые часы словами от одного до двенадцати поддерживаются. Поддерживаются также «15 октября», «15 октября 2027 в 18:00», «в этот четверг», «в следующую пятницу» и даты без времени (09:00 по Москве). «Этот» означает день текущей недели, «следующий» — следующей недели; уже прошедший день текущей недели отклоняется. Даты без года выбираются в ближайшем будущем, включая ближайшее 29 февраля. Сложные разговорные даты могут потребовать ручной установки: бот не является языковой моделью для извлечения сроков. Все автоматически найденные сроки требуют подтверждения. Дата без года означает ближайшее будущее вхождение; одно время означает ближайшее такое время.

Альбом Telegram сохраняется как одна задача; дополнительные отдельные сообщения прикрепляются через кнопку «Добавить вложения». После перезапуска незаконченный ввод сохраняется. Стикеры и другие неподдерживаемые типы не создают задачу.

Текстовые задачи и фото не отправляются нейросети. ГС распознаются локально; worker ограничен тайм-аутом. При ошибке используй повтор или ручной ввод.

Экспорт содержит личные задачи и Telegram file_id, но не загружает сами медиафайлы. Команды импорта JSON пока нет. Для полной резервной копии используйте SQLite backup API либо остановите бота перед копированием БД; у работающей SQLite данные могут находиться в файле WAL.

Секреты и БД исключены из Git и Docker build context. Запросы параметризованы, HTML экранируется, доступ к задачам и вложениям проверяется по владельцу. Тесты проверяют даты, альбомы, перенос с вложениями, две кнопки уведомления, чужой доступ, сохранность после переоткрытия БД, подтверждение расшифровки и отсутствие повторной отправки. Telegram и распознавание в тестах заменены имитацией: настоящий запуск требует токена и доступа к сервисам.
